# DID 稳健性检验 Skill

## 触发条件

当任务满足以下任一条件时调用本 Skill：

- 用户要求"对某个 DID/面板回归做稳健性检验"、"跑一遍平行趋势/安慰剂"、
  "检查结果是否稳健"、"换控制变量/聚类/样本再跑一次"等。
- 用户提供了一个面板数据 + 一个主回归，要求系统性地检验其稳健性。
- 不适用于：单次简单回归估计（无稳健性要求）、非因果推断类描述统计。

## 背景知识

- **DID 基本设定**：结果变量 $Y_{it}$ 对处理变量 $D_{it}$ 回归，含个体固定效应 $\alpha_i$ 与时间固定效应 $\lambda_t$，
  即 $Y_{it} = \alpha_i + \lambda_t + \tau D_{it} + X_{it}'\beta + \varepsilon_{it}$，标准误聚类到个体。
- **识别假设**：平行趋势、无预期效应、无溢出（SUTVA）。
- **常规稳健性检验**：平行趋势（处理前系数联合检验）、安慰剂（伪处理/伪时间）、替换结果变量、
  改变控制变量、改变聚类层级、极端值处理（winsorize）、样本调整。
- **主题稳健性检验**：处理变量测量方式、异质性（分组）、机制（交互项）、排除竞争性解释（高维固定效应）。
- **常见陷阱**：个体固定效应会吸收个体层面不随时间变的变量（共线 → 秩亏、SE 为 NaN），
  处理时间统一时事件研究虚拟变量与年份固定效应可能共线。

## 工作步骤

1. **识别数据结构**：先读 README/数据文件，识别并确认：结果变量 `{outcome}`、处理变量 `{treatment}`、
   个体维度 `{id}`、时间维度 `{time}`（在 README 或代码注释中确认，不要臆测变量名）。
2. **复现主回归**：按 README/代码注释的设定复现主回归（个体 FE + 时间 FE + 聚类标准误），
   确认基线系数与已有结果一致。
3. **逐项稳健性检验**（按需执行）：
   - 常规：平行趋势联合检验 → 安慰剂 → 替换结果变量 → 改变控制变量 → 改变聚类层级 →
     极端值处理 → 样本调整。
   - 主题：处理测量方式 → 异质性分组 → 机制交互 → 高维固定效应。
4. **输出与留痕**：每项检验输出结果表/图到 `output/`，并把该项的 **Prompt（四要素：目标/边界/验证/汇报）**
   与结果摘要、观察存为 `prompts/robustness/*.md`。
5. **汇总**：生成一张稳健性汇总表，逐项判定"通过 / 警示 / 失败"，给出依据。

## 检查清单

- [ ] 是否先读数据/README 识别变量，而非硬编码？
- [ ] 主回归是否复现？基线系数与已有结果一致？
- [ ] 是否检查了"个体固定效应下 time-invariant 变量共线"问题（SE 是否正常）？
- [ ] 平行趋势：处理前系数联合检验是否报告 F/p？
- [ ] 安慰剂：伪估计分布是否报告均值/区间，并与真实估计对比？
- [ ] 每项检验是否输出结果文件 + 独立 Prompt Markdown？
- [ ] 是否存在"越界表述"（如把合成数据结果说成真实因果）？
- [ ] 汇总表是否给出"通过/警示/失败"及依据？

## 边界条件

- **不做**：不修改原始数据（`data/` 只读）；不虚构文献；不把合成/演示数据的结论解释为真实因果证据；
  不越界修改论文（除非明确授权）。
- **停止条件**：当输入数据、变量或回归设定不明确时，停下询问，不擅自臆测。
- **提示**：聚类标准误为 NaN 时，优先排查 time-invariant 变量与个体 FE 的共线问题，而非直接忽略。

## 验证方式

- **主回归复现**：基线系数与 README/已有输出一致（量级、方向）。
- **结果合理性**：各项检验的系数方向、显著性是否符合"稳健"预期；异常项必须说明原因。
- **可复现**：脚本能从原始数据重跑；随机检验（如安慰剂）固定随机种子。
- **可审计**：每项检验有独立的 Prompt Markdown + 结果文件；汇总表可追溯到各单项。

## 如何迁移（一般适用性论证）

- **需要改的地方**：数据集路径、变量名（结果/处理/个体/时间）——由 AI 先读 README/数据自动识别；
  处理时间（交错与否）影响事件研究写法；聚类层级按研究设计调整。
- **不需要改的地方**：完整的工作步骤（先识别→复现→逐项检验→留痕→汇总）、
  检查清单（共线、SE、平行趋势、安慰剂、越界表述）、边界条件与验证方式。
- **例**：换成"最低工资对就业"或"医保对健康"，只需重新识别 `{outcome}/{treatment}/{id}/{time}`，
  六模块框架与检查清单完全复用 → 说明本 Skill 是可迁移的制度，而非本项目定制脚本。
